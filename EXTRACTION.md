Studio owns its source, installation, and macOS/Linux acceptance. Dotfiles retains the shared resource authors and registers `~/src/studio` as `studio` in `config/project-updates.toml`. There is no pre-extraction application database to migrate. Existing Beads data and unrelated Pi sessions remain outside this extraction. Studio retains its normal persistent attempt and recovery records for future use.

Optional integrations are disabled by default and are admitted only when configured and present. Core installation and standalone acceptance do not require Beads, Zellij, worktree manager, or Octo; use `--with-integrations` for native delegation acceptance.

`vendor/pi-components` retains the shared selector, condition status and activity primitives, conditions panel, two-column status dock, and foldable inspector from [dotfiles commit b4163590](https://github.com/lanej/dotfiles/tree/b416359039587ca36d0ec9bc0f7509da0833b933/tools/pi-components). The original package owns generic presentation and interaction; Studio owns Socrates properties, evidence, freshness, activity events, and persistence. Refresh the exported sources together and run both the component package's strict check and Studio's native `test:socrates-ui` check. The selector copies Pi 1.6 readonly Markdown rows at its mutable row-composition boundary. Source export and installation select Git-visible files; snapshots without Git use the explicit `source-files.json` generated at export. Ignored local files are outside that boundary.

Studio applies [a layout patch](patches/pi-tui-right-column.patch) to its installed Pi TUI 1.6.0. It reserves horizontal space for an optional component in both terminal rendering modes. In 256-color mode it also allows near-neutral backgrounds to use the closer xterm gray. This keeps the native Nord panel and selection distinguishable. The Socrates extension owns the sidebar content and breakpoint. When upgrading Pi, verify wrapping, focus, resize, collapse, and evidence inspection with `bun run test:socrates-ui`.

Studio applies a [coding-agent patch](patches/pi-coding-agent-1.6.0.patch) to the pinned Pi 1.6.0 interactive host. The native editor handles guidance and queueing while the assignment option disables shell commands, external editor and session navigation at their entry points. The controller starts the worker turn and retains its result. Pi drops guidance if its turn settles during input preflight. When upgrading Pi, inspect new built-in command and shortcut paths and run the `assignment-input` and `interactive-dispatch` native cases.

The coding-agent patch also fits inline images to their source size and pane by default, retains an explicit terminal-cell width setting, and renders expanded thinking as upright Markdown across the available conversation width. It composes those presentation changes with the assignment input restrictions in one package patch. When upgrading Pi, run the inline-image and thinking-display tests as well as native assignment-input and Socrates UI acceptance.

Studio's diagram aliases use the coding-agent patch to call their canonical tool through Pi's permission and result hooks. The host permits this delegation only for an active alias registered by the same extension. The diagram tools keep their model-only exposure. When upgrading Pi, run `bun run test:pi-native` for the tool hooks and `uv run --script acceptance/diagram.py --mermaid` with Mermaid CLI for the inline image and replay.

Studio retains planning schemas, guarded atomic writes, revision calculation, Pi admission/outcome attribution and the Zellij launcher. Update the immutable package pin and lock together, verify standalone installation, and run Studio native document acceptance across the packaged boundary.
