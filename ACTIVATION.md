# Native Studio activation

Studio's extension publishes a private Unix control endpoint and owned runtime record under its external state directory. Inventory reports the native Pi session ID, transcript path, selected leaf, cwd, process start identity and a random runtime incarnation. The running artifact identity combines the loaded immutable Studio release, its selected Pi host, the actual kernel-mapped shared Bun executable bytes, and the declared Bun minimum. Studio accepts a qualifying environment runtime and does not install a private interpreter. A source checkout or different loaded host receives a distinct identity; changed or unavailable mapped-image evidence blocks activation.

Managed launchers use the selected unbundled CLI from the pinned Pi package so Studio and the host share the actual SDK dispatch and result-writer classes. Native Bash admission remains held through asynchronous user handlers, custom remote execution, and result recording; pending or uncertain authority refuses checkpointing. A bundled or opaque host without those verified boundaries remains intact and incomplete.

The control protocol is version 1. `inventory` and `verify` are read-only. `checkpoint` requires the inventoried process incarnation, selected replacement identity, operation UUID and private checkpoint directory. It fences new input and provider/tool operations, writes cancellation intent durably, calls Pi's native abort once, and confirms only after Pi and its tool handlers settle. Active native tools and subprocesses are refused before cancellation because the pinned shell abort uses forced termination. Queued input, admitted asynchronous commands, unresolved delegated work, a background runtime authority without native checkpoints, disabled transcript persistence, or a refused cancellation blocks replacement. Repeated observation of one operation does not repeat cancellation. No credential values or signing keys enter a checkpoint.

A confirmed checkpoint retains the exact native transcript and selected leaf, cwd, recoverable editor text, managed attempt ID and whether work was interrupted. `stop` requires that confirmed operation and requests Pi's graceful shutdown. Interrupted operations are never submitted again. An uncertain stop or launch remains uncertain until runtime evidence resolves it.

Terminal-owned Pi applications declare a restoration owner and defer their launch to Zellij. Zellij must launch each retained restore argv exactly once from a verified terminal environment, then Studio verifies the new native runtime and reconciles its managed attempt binding. `studio-activation-restore` is an extension command that navigates to the saved native branch without a summary or model call and restores the retained editor text. It refuses another transcript, cwd, selected artifact or branch.

Legacy Pi processes without the native control remain intact. Likewise, absent terminal checkpoint support or an independent terminal environment baseline reports incomplete activation; installing a bundle does not establish that such a running session loaded it.
